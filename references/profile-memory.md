# 人物画像与记忆规范

## 数据边界

私有根目录由用户授权，位于发行目录外。使用 Python 标准库的本地 SQLite 文件作为事务容器，不需要数据库服务器。people 与 aliases 负责身份定位；claims 是每人最多48条、每条最多1000字符的决策画像；sources 单独保存授权留存的文本；claim_sources 关联证据。SELF 表示用户自身。人物资料没有共享默认实例。

短期聊天只存在本轮模型上下文中，未经长期保存授权不调用 source-add。原始视频由宿主授权位置管理；本地工具不自动复制或删除外部原件。导入转写时保存来源、核对状态和同一案例 event_group，避免把续集当独立证据。

## 晋升与更新

claim 字段：id、person_id、content、evidence_type、source_refs、confidence、status、reason、updated_at。类型为 fact、statement、user_statement、inference、unknown；可信度为 high、medium、low、unknown，是定性判断而非概率。状态为 active、pending、corrected、revoked。来源必须真实存在、属于同一人物且不是草稿。

仅 stable_fact、preference、boundary、correction、stable_pattern 可晋升。稳定模式至少需要两个独立 event_group；普通问候无需保存。每次 upsert 传 expected 人物版本，事务内检查版本、合并结论和关联。重复来源按人物、类型、内容哈希去重；相同结论原位更新。达到画像上限时拒绝追加，要求合并，不静默丢弃边界。

## 关联删除

删除 source：定位全部支持结论 → 删除来源和关联 → 有其他来源则保留结论，无依据则删除 → 清理相关理论引用、分支历史和缓存 → 同事务提交。用户明确选择保留脱敏总结时，须先提供并核对替换后的摘要，不能把原文自动称为脱敏。

删除 person：同事务清除画像、原始留存、别名、人物配置、分支及历史、缓存，留下不含私密内容的 ID 删除标记，防止旧导入自动重建。重新创建需要 allow_recreate=true 的明确操作。外部原件、既有导出、平台历史版本和备份不能由本地工具保证清除。

## 恢复与导出

事务失败会回滚，不存在先改画像再改错索引的半成功状态。export 使用 SQLite backup 获取一致快照并核验完整性；导出包含有效数据、保留的版本历史和私人配置，未加密。restore 验证 schema 与数据库完整性后写入新的私有目录，不覆盖现有数据。新建目录用于审查或回滚，保留原目录。

旧版 migrate 默认 dry-run；显式 apply 后逐操作事务提交。重试以来源哈希和结论内容去重，可从已保存的迁移映射恢复。旧画像仅作为历史总结，不假装重读了原截图；自动迁移结论标记 unknown/pending，用户明确意愿和确认偏好另行通过私有配置继承。

## 连续使用与时效

storage-bind只把经授权验证的目录定位保存到私人状态文件，使用版本校验、独占写锁和临时文件替换。它不存聊天原文、不扫描工作区，也不代表宿主持久存储。没有有效绑定时context明确降级；缺失数据库不得自动新建。storage-status的available只指文件存在，health才检查数据库。

storage-backup在全新目录生成SQLite快照及恢复清单，含大小、哈希、schema与生成时间。恢复先校验，再复制校验并检查完整性和外键，只发布到新目录，之后单独绑定；中断后不猜测已恢复。两文件均含或关联私人资料，未经授权不得外发。清单哈希只能查损坏，不是加密或真实性签名。外部持久存储依赖宿主授权工具和真实回执。

context只在精简画像上附加temporal读取提示，不写入claims，不改变pending或active。明确“有效至”可按内容日期核对；“今天、这周”使用updated_at估计复核窗口，并注明该时间不是聊天发生时间，因此仍需核实适用性；“最近、暂时”始终要求结合语境，不编造截止日。过期边界继续作为历史边界，必须有明确新意愿才能改变。缓存不存每日时效结果，每次按as_of重新核对，避免隔日命中旧判断。

user-status为只读查询，仅合并global、SELF及指定人物的设置，返回逐字段来源和版本；不会读取原始sources正文或遍历其他画像。40条起建议在维护时合并，48条仍为硬上限；不静默删去证据、待核实结论或边界。
