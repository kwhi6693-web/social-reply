# 八层与四模块架构

| 逻辑层 | 实际模块 | 运行对象 |
| --- | --- | --- |
| L1 人物画像 | Profile & Memory | SELF与目标人物的精简claims |
| L2 记忆管理 | Profile & Memory | 独立sources、来源关系、短期上下文及删除标记 |
| L3 推荐回复 | Runtime Engine | 宿主一次必要判断及唯一成稿 |
| L4 链路优化 | Runtime Engine | 稳定ID、主题索引、版本缓存与Benchmark |
| L5 基础理论 | Knowledge Engine | 32条主干、候选导入、独立版本 |
| L6 理论延展 | Knowledge Engine | 默认关闭、审核、人物范围、撤销与回滚 |
| L7 自定义指令 | Configuration & Integrity | 单次、人物、全局及长期偏好 |
| L8 可靠性保护 | Configuration & Integrity | 权限、事务、导出恢复、ZIP及发布验证 |

四个模块分别是 scripts/sr/runtime.py、memory.py、knowledge.py、integrity.py；social_reply.py 提供 JSON 命令入口。它们按需在一个本地进程中运行，没有常驻服务和多 Agent 运行依赖。宿主负责自然语言理解、图片或视频理解及生成；工具负责可验证的数据操作，不伪装为独立生成模型。

FAST：直接定位人物、读取当前相关配置和精简画像、检索当前主题、仅加载批准启用的分支。STANDARD：身份确认、重要增量、复杂冲突、局部复盘。DEEP：资料导入、理论学习、迁移、全局审计和恢复。深度处理不是日常回复前置步骤。

本地 SQLite 是标准库嵌入式事务文件，使用普通B树索引保证按人物和主题定位，无服务器或向量引擎。选择它是为解决多对象关联删除和原子更新，不以资料增大为理由引入服务。发行目录不放运行数据库。

缓存存放于私有事务文件，只含精简决策数据；缓存键绑定运行引擎、人物、用户配置、Core和分支版本。升级后不复用旧引擎缓存，避免绕过新完整性规则。每次先核对相关版本，新增无关人物不使当前人物缓存失效。原始聊天不进入缓存。未配置缓存或存储不可用时降级到本轮事实，不能声称加载成功。

性能报告分别记录本地上下文准备延迟、SQL读取次数、逻辑文件数、UTF-8字节数及可用时的token计数。宿主不暴露首token时间、实际计费token和生成完成时间时，相应字段为未验证；不可将本地毫秒数宣传成模型回复速度。
